Agentic Slime System Overview

Non-invasive agent-env training stack: configuration is resolved once, server ops materializes node-local runtimes and data, launch manages distributed services, and Slime consumes a pure env-server rollout contract.

Source of truth

Run profile

configs/agent_env/runs/*.env

  • Select env, model, train, topology, optional aux.
  • Keep experiment wiring thin.

Owned configs

Model profile owns model identity. Train profile owns algorithm, batch, token budget, sync mode, and checkpoint policy. Reward profile owns reward composition.

Env config

examples/agent_env/<env>/env_config.yaml owns task semantics, parser, data settings, and env server settings.

Launch contract

Launcher

scripts/utils/launch_agentic_training.sh

  • Loads profiles once.
  • Writes run-local resolved_launch.env and resolved_train.env.
  • Stops bench on selected train nodes.

Server ops

${ROOT_DIR}/scripts owns node materialization, data packs, watchdog, bench, and SSH fanout.

Keepalive boundary

Watchdog and bench are utilization-based and framework-agnostic. Train exit calls run_bench.sh.

Distributed runtime

Ray + services

Node indexes come from configs/nodes/*.txt. Topology profiles select nodes by index, not concrete IPs.

Node 0 Ray head Router Actor train Env server
Nodes 1-2 Ray workers SGLang rollout engines Env servers
Node 3 Optional aux endpoint Otherwise bench
Node-local cache /tmp/server-ops-envs /tmp/server-ops-runtime

Remote locality

Node-local runtimes are validated on the node that executes them. Control hosts only resolve launch intent and remote paths.

Training loop

Slime async loop

Slime owns actor updates, rollout engines, weight sync, batching, logprobs, KL, checkpointing, and W&B reporting.

Generic rollout

examples.agent_env.fully_async_rollout owns sample shape, env HTTP leases, dumping, infra discard, and GLM-style padding.

Reward path

Reward implementation is selected by env config. RM and post-process produce final reward tensors before dynamic sampling filters groups.

Artifacts

Durable outputs

${ROOT_DIR}/runs/<project>/<name>

  • Logs and resolved configs.
  • Rollout cases and discard dumps.
  • Checkpoints capped by train profile.

Observability

W&B tracks rollout reward, truncation, format/action rates, PPO KL, clipfrac, entropy, grad norm, wait time, and throughput.

Failure behavior

Launch failure or train exit should restore bench. Watchdog is the fallback when GPUs stay idle.

End-to-end data flow
1. Resolve profiles Run, model, train, topology, aux, and env config resolve into run-local launch/train contracts.
2. Start services Ray head/workers, env servers, router, optional aux endpoint, and SGLang rollout engines come up.
3. Rollout Env server runs the episode and calls the Slime policy gateway; the gateway records tokens, logprobs, masks, and traces.
4. Reward and filter Reward implementation fills reward fields; dynamic sampling drops zero-variance groups.
5. Train Actor consumes batches, computes PPO/GRPO losses, updates weights, then syncs rollout engines.
6. Persist Metrics, dumps, resolved configs, and capped checkpoints are written under the run directory.
